# Self-paced audio

Audio adds a presentation and speech layer to existing word practice. It does not change target selection, exact spelling, grouping, correction rules, or the WPM formula. Transcripts and continuous dictation are outside this release.

`WordPracticeProjection.prompt` identifies a group/pass and its native source boundary. Its ID advances after an exact final tail, before that tail receives a separator. Committing the separator keeps the same ID; editing the tail restores the previous one. Midgroup mistakes keep the same prompt. Speech consumes this logical projection rather than caret movement, so arrow keys, hint toggles, replay, and focus changes cannot create attempts or errors.

`SpeechAdapter` isolates browser voice discovery, playback, cancellation, and callbacks. The browser adapter filters on `localService` and English language tags, then selects the saved available voice, local English default, or first local English voice. It subscribes to `voiceschanged` for delayed discovery. The API and local/remote distinction are documented by [MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis) and [localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService).

Clear instructor is the default speech option. Automatic voice selection prefers it, while an explicitly saved available browser voice takes precedence. Audio remains off unless enabled. The former experiment flag is retained only for backup compatibility and has no effect on availability. Voice selection remains personal; shared v1–v5 formats are unchanged.

The recorded adapter receives structured prompt words with the qualifying outline and effective dictionary pronunciations. It chooses a compatible pronunciation in dictionary order, preferring explicit clear citation forms for standalone practice and respecting personal corrections; shared tests use the bundled dictionary. No compatible recording, preparation failure, or a 2.5-second preparation deadline switches the entire group to a local English browser voice and shows “Using device voice.” A late recording cannot replace that fallback mid-group. If no fallback voice exists, it reports an error. Playback failure after starting offers Replay; answers remain concealed.

The loader prioritizes the current group, then prepares the next 20 target words with at most four concurrent fetch/decode jobs. Sprite work is deduplicated. Ordinary prompt changes retain useful preparation; restart, settings, navigation, and focus loss cancel it. Compressed audio has a 32 MiB in-memory LRU and best-effort CacheStorage budget; extracted clips have a 24 MiB LRU. Full decoded sprites are released after extracting requested clips. Storage failure affects caching, not playback correctness.

Most sprites use mono Opus VBR, starting at 10 kbps and increasing only when decoded acoustic evidence degrades. Every sprite remains capped at 48,000 bytes and 40 seconds; packs split when a higher bitrate exceeds the byte limit. Clips that still fail acoustic preservation use 24-bit lossless FLAC, under the same byte and duration caps. The loader decodes both formats into the same PCM playback path. Common words are packed separately from other eligible vocabulary, with deterministic chord ordering within each partition. Hashed manifests identify pronunciation variants, checksums, and integer 24 kHz sample boundaries. Groups concatenate clips with their existing guards and no additional pause, then play a temporary WAV through a pitch-preserving audio element. Temporary URLs and playback handlers are cleared on completion/cancellation. Static headers permit these local blobs and cache hashed audio immutably.

The released collection has 2,360 words (878 common words), 2,394 pronunciation variants, and no corpus fallback entries. Its 141 sprites total 4,571,720 bytes: 125 Opus sprites and 16 lossless sprites.

Production generation uses the exact approved synthetic reference in `data/audio`, pinned Qwen Base revision, and locked audition environment. No person's voice recording is used. Generation and raw/prepared word masters remain in ignored `.audio-audition/production`; only curated generation inputs, recipes, coverage/provenance, manifest, and production audio files are committed. The old audition harness remains available. Models and Python are unnecessary for normal development builds, CI, or browser use.

```sh
npm run audio:catalog   # Derive eligible words and outline/pronunciation targets
npm run audio:generate  # Resumable local inference; Apple Silicon environment
npm run audio:generate -- --reviewed-only # Restore pinned approved sources; no inference
npm run audio:pack      # Pack and acoustic-check masters; requires FFmpeg + local reviewer
npm run audio:patch     # Publish approved repairs while preserving all other sprites
npm run audio:check     # Read-only catalog, coverage, checksums, and cap validation
npm run audio:audit -- --transcribe-flagged # Optional local recognition of packed clips
npm run audio:quality   # Screen decoded clips for silence and quiet artifacts
npm run audio:generate -- --repair-audit   # Retry flagged pronunciations
npm run audio:generate -- --repair-unverified # Retry remaining unresolved recordings
npm run audio:generate -- --repair-quality # Regenerate signal failures
```

The local audit checks the actual decoded production clip boundaries with a pinned [English phoneme recognizer](https://huggingface.co/vitouphy/wav2vec2-xls-r-300m-timit-phoneme), comparing its acoustic output with the outline-specific dictionary pronunciation. It allows narrow American allophones while preserving contrasts such as ties/tees, hat/hot, and than/then. Pinned Whisper Small independently transcribes flagged clips without being shown their expected spelling. These are screening tools, not a guarantee of natural or correct speech. Results and decoded-PCM checksums are cached in ignored storage; models are not deployed. Automatic stem extraction has been removed: new inference generates a complete word, and a rejected pronunciation remains unpublished for review. Legacy context fields and the original reviewed null input remain as provenance for old cached recordings.

Listening approval binds the exact audition PCM checksum to its word and candidate ID. The repair set contains 42 selected recordings, including the 35 fresh isolated-word replacements reviewed after the stem-cutting problem. Their approved float WAV inputs, generation settings, positive ratings, and fixed encoded assets are retained in `data/audio/repairs` and the production asset directory. Phoneme-model disagreements remain visible in the review; they do not justify chopping speech or changing the dictionary. Opus encodings of these sources must preserve the recognized phone sequence and its likelihood; otherwise the bitrate increases, with bounded 24-bit lossless conversion as the last option. Already encoded, approved auditions keep their exact bytes.

`audio:patch` replaces approved clips without re-encoding other recordings and retains their original pronunciation order. The current repair preserves all 2,352 other variant recordings. Repeating the command with the same inputs makes no changes. The JavaScript release check verifies source WAV samples, approval and asset checksums, codec evidence, complete coverage, and unchanged recordings from earlier listening approvals. A full `audio:pack` can change other packed clips and therefore requires renewed listening approval if those checks detect drift. Ordinary CI does not require Python, FFmpeg, or model downloads.

Packing also compares each decoded clip with its lossless source. A changed greedy phone label can reflect a near tie, so the check measures the source path’s CTC likelihood loss and raises the bitrate when the increase exceeds 0.25 nats per phone. It never supplies the expected word to recognition. The committed `data/audio/quality.json` binds every signal/acoustic result to the manifest, source and decoded checksums, model revision, and review policy. Normal JavaScript builds validate that report without downloading models.

Signal checks flag excessive boundary silence, internal gaps, extended quiet tails, silent output, and unusually long isolated words. Only excessive near-silent boundaries can be trimmed automatically, retaining 80 ms guards and quiet consonants. Internal gaps and uncertain breath artifacts require regeneration. Both packing and the release check reject incomplete pronunciation coverage; unresolved corpus words cannot be replaced by device speech. Run the comparison-policy and signal tests with `PYTHONPATH=scripts/audio-audition python3 -m unittest discover -s scripts/audio-audition -p 'test_*.py'`. Generation overrides remain explicit. Selected difficult contrasts require an unchanged decoded phone sequence in addition to the likelihood check. Unrestricted word lists choose an explained outline when available, avoiding an unnecessary voice fallback caused by unclassified dictionary alternatives. Final measured coverage, encoding size, and inference time are in `data/audio/provenance.json`; release browser measurements are recorded separately.

The updated M1 Max benchmark at 5 Mbps and 100 ms response latency measured native playback start at 288.3 ms cold and 2.6 ms prepared (95th percentile of ten trials using the largest near-limit sprite). Prepared playback met the under-100-ms target; cold playback exceeded the 250-ms target by 38.3 ms. A 225-word run with a different sprite for every word had no transition waits of 100 ms or more after preparing its first 21 targets. Preloading took 2.62 seconds; three-word cold preparation took 401 ms. The largest observed caches were 16.0 MB PCM and 10.8 MB compressed, with four requests active at most. See `docs/audio-performance.json` for raw timings, conditions, and limits; these are measurements, not universal latency guarantees.

`PromptSpeaker` requires initial activation, cancels superseded utterances, and ignores stale callbacks using a generation counter. Missing voices, denied playback, thrown errors, and an eight-second start timeout report a concise failure. The session clock begins on the first valid start callback. Cancellation never pauses an already-started clock. Space or Play activates a fresh test; visible typing also activates speech without consuming the first character. Hidden tests show “Press space to start.” Enter and Restart activate playback immediately, even before the first session. The native input buffer accepts early typing while the first cue stays queued until its start event establishes the clock; logical prompt sequencing then resumes. Restart resets the clock until the new utterance starts. Page/window focus loss cancels speech without automatically replaying on return.

Full keeps the measured passage. Current measures only the prompt's group and renders complete rows. Hidden renders entered text only, wrapping it into explicit rows using the fixed typography; no expected-word elements, measurement ruler, titles, chord answers, or accessibility descriptions are mounted before reveal. Its empty geometry is independent of expected word lengths. Raw pending input has a neutral annotation. Reveal uses prompt-local state and clears on progress; it does not write the hint preference. Hidden answers stay concealed when speech is unavailable.

Listening preferences live in the session profile and backups. The preferred voice URI is a separate personal field. Old profiles migrate to audio off, Full, 1× and Automatic voice. Audio-off sessions always show Full while retaining the inactive display and rate. Shared v5 links carry only audio, display, rate, and existing test constraints; v1–v4 are unchanged and explicitly disable audio.

Automated tests cover prompt/tail sequencing, group retries and recovery, strict corrections, raw outlines, exact homophones, native buffer edits, playback timing, restart, deadlines, cancellation, stale callbacks, local-only discovery, missing/blocked/failed playback, hidden-answer exposure, profile/backups, wire fixtures, and shared-state editing/save/exit. Release QA also checks desktop/320px/393px layouts, themes, ten dots, long input, focus recovery, and native local-voice playback through the production build.
