# Self-paced audio

Audio adds a presentation and speech layer to existing word practice. It does not change target selection, exact spelling, grouping, correction rules, or the WPM formula. Transcripts and continuous dictation are outside this release.

`WordPracticeProjection.prompt` identifies a group/pass and its native source boundary. Its ID advances after an exact final tail, before that tail receives a separator. Committing the separator keeps the same ID; editing the tail restores the previous one. Midgroup mistakes keep the same prompt. Speech consumes this logical projection rather than caret movement, so arrow keys, hint toggles, replay, and focus changes cannot create attempts or errors.

`SpeechAdapter` isolates browser voice discovery, playback, cancellation, and callbacks. The browser adapter filters on `localService` and English language tags, then selects the saved available voice, local English default, or first local English voice. It subscribes to `voiceschanged` for delayed discovery. The API and local/remote distinction are documented by [MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis) and [localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService).

Experimental features adds Clear instructor to the Voice selector without enabling Audio or changing the saved voice. The flag and voice are personal profile/backup fields; older profiles default to the experiment off. Disabling the flag uses ordinary browser voice selection and retains the recorded preference. Shared v1–v5 formats are unchanged.

The recorded adapter receives structured prompt words with the qualifying outline and effective dictionary pronunciations. It chooses a compatible pronunciation in dictionary order, including personal corrections; shared tests use the bundled dictionary. No compatible recording, preparation failure, or a 2.5-second preparation deadline switches the entire group to a local English browser voice and shows “Using device voice.” A late recording cannot replace that fallback mid-group. If no fallback voice exists, it reports an error. Playback failure after starting offers Replay; answers remain concealed.

The loader prioritizes the current group, then prepares the next 20 target words with at most four concurrent fetch/decode jobs. Sprite work is deduplicated. Ordinary prompt changes retain useful preparation; restart, settings, navigation, and focus loss cancel it. Compressed audio has a 32 MiB in-memory LRU and best-effort CacheStorage budget; extracted clips have a 24 MiB LRU. Full decoded sprites are released after extracting requested clips. Storage failure affects caching, not playback correctness.

Sprites are mono Opus at 10 kbps VBR, capped at 48,000 bytes and 40 seconds. Common words are packed separately from other eligible vocabulary, with deterministic chord ordering within each partition. Hashed manifests identify pronunciation variants, checksums, and integer 24 kHz sample boundaries. Groups concatenate clips with their existing guards and no additional pause, then play a temporary WAV through a pitch-preserving audio element. Temporary URLs and playback handlers are cleared on completion/cancellation. Static headers permit these local blobs and cache hashed audio immutably.

Production generation uses the exact approved synthetic reference in `data/audio`, pinned Qwen Base revision, and locked audition environment. No person's voice recording is used. Generation and raw/prepared word masters remain in ignored `.audio-audition/production`; only the curated reference, recipes, coverage/provenance, manifest, and production Opus files are committed. The old audition harness remains available. Models and Python are unnecessary for normal development builds, CI, or browser use.

```sh
npm run audio:catalog   # Derive eligible words and outline/pronunciation targets
npm run audio:generate  # Resumable local inference; Apple Silicon environment
npm run audio:pack      # Pack and decode-check masters; requires FFmpeg
npm run audio:check     # Read-only catalog, coverage, checksums, and cap validation
```

The optional local `scripts/audio-audition/review.py` uses a pinned multilingual phoneme recognizer to flag potential pronunciation problems. Its output is a screening aid, not proof of pronunciation quality: isolated words, American vowel mergers, and final consonants can be misrecognized. Generation overrides and unresolved fallback cases remain explicit. Final measured coverage, encoding size, and inference time are in `data/audio/provenance.json`; release browser measurements are recorded separately.

The controlled M1 Max benchmark at 5 Mbps and 100 ms response latency measured native playback start at 244 ms cold and 3.3 ms prepared (95th percentile of ten trials). A 225-word run with a different near-limit sprite for every word had no transition waits of 100 ms or more after preparing its first 21 targets. Total sprite traffic was 10.8 MB including that preload, which took 2.38 seconds. The largest observed caches were 12.0 MB PCM and 10.8 MB compressed, with four requests active at most. Three-word cold group preparation took 388 ms. See `docs/audio-performance.json` for raw timings, conditions, and limits; these are measurements, not universal latency guarantees.

`PromptSpeaker` requires initial activation, cancels superseded utterances, and ignores stale callbacks using a generation counter. Missing voices, denied playback, thrown errors, and an eight-second start timeout report a concise failure. The session clock begins on the first valid start callback. Cancellation never pauses an already-started clock. Space or Play activates a fresh test; visible typing also activates speech without consuming the first character. Hidden tests show “Press space to start.” Enter and Restart activate playback immediately, even before the first session. The native input buffer accepts early typing while the first cue stays queued until its start event establishes the clock; logical prompt sequencing then resumes. Restart resets the clock until the new utterance starts. Page/window focus loss cancels speech without automatically replaying on return.

Full keeps the measured passage. Current measures only the prompt's group and renders complete rows. Hidden renders entered text only, wrapping it into explicit rows using the fixed typography; no expected-word elements, measurement ruler, titles, chord answers, or accessibility descriptions are mounted before reveal. Its empty geometry is independent of expected word lengths. Raw pending input has a neutral annotation. Reveal uses prompt-local state and clears on progress; it does not write the hint preference. Hidden answers stay concealed when speech is unavailable.

Listening preferences live in the session profile and backups. The preferred voice URI is a separate personal field. Old profiles migrate to audio off, Full, 1× and Automatic voice. Audio-off sessions always show Full while retaining the inactive display and rate. Shared v5 links carry only audio, display, rate, and existing test constraints; v1–v4 are unchanged and explicitly disable audio.

Automated tests cover prompt/tail sequencing, group retries and recovery, strict corrections, raw outlines, exact homophones, native buffer edits, playback timing, restart, deadlines, cancellation, stale callbacks, local-only discovery, missing/blocked/failed playback, hidden-answer exposure, profile/backups, wire fixtures, and shared-state editing/save/exit. Release QA also checks desktop/320px/393px layouts, themes, ten dots, long input, focus recovery, and native local-voice playback through the production build.
